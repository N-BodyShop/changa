ChaNGa SIMD Port: Benchmark Results
===================================

Summary
-------
The SIMD port (ChaNGa-test/changa, commit 84276cd) produces output
bit-identical to the baseline fork (ChaNGa_FORK_AMF599/changa) for:

  - SSE2 double       teststep, testcosmo, restart
  - AVX double        teststep, testcosmo, restart
  - SSE2 float        teststep (max rel diff 0.000e+00), restart

Testcosmo is not compared for float (no float reference exists).

Average speedup over the fork, AVX double, is about 15% on teststep and
about 5% on testcosmo. SSE2 float is about 15% and 6%. SSE2 double is
about 3% on teststep and slightly slower (-2%) on testcosmo.

Sources
-------
Test variants: suite run "verify_after_float_fix" (last full validated
  suite run). Results file:
  ChaNGa_benchmark/suite/results/verify_after_float_fix.tsv

  This run predates two doc-only edits to gravity.h. Those edits fixed
  two bucket-overload signatures that had been cut off. After the fix,
  the AVX double build was re-verified (teststep x3, restart), and the
  committed tree was re-verified (testcosmo AVX, see below).

Fork baseline: fresh rerun in the same session, so load is comparable.
  ChaNGa_benchmark/suite/results/fork_latest.tsv

Machine load during runs was 5 to 11 (shared machine), so timings are
indicative. Bit-exactness is not affected by load.

Wall-clock times are in milliseconds. Mean is over reps. Yield is
(fork - ours) / fork, so a positive value is faster than the fork.

Notes
-----
- Round-4 numbers in ChaNGa_docs/RESULTS_HISTORY.md are five-run sums at
  mixed load. They are not per-run values and are not used here.
- Restart is a single run per variant, so its yield is less reliable.
- SSE2 double testcosmo is slower than the fork in this run. That is
  within the load noise seen here, but it is the one case where the port
  does not win. Not investigated further.
